# Lesson 36 — Collections in Python

## 📌 Overview

Python provides the `collections` module, which extends the functionality
of Python's built-in data structures.

It provides specialized container types that make data processing more
efficient, readable, and maintainable.

In this lesson, we will explore the most useful tools from the
`collections` module and apply them to practical Network Automation
scenarios.

The focus is not only on learning the available classes, but also on
understanding when and why to use each data structure in professional
Python applications.

---

## 🎯 Learning Objectives

By the end of this lesson, you will be able to:

- Understand the purpose of the `collections` module.
- Use `Counter` to count elements and analyze network events.
- Use `defaultdict` to group devices and network logs.
- Use `deque` to implement efficient queues and event buffers.
- Use `namedtuple` to represent structured records.
- Understand `OrderedDict` and its specialized use cases.
- Understand `ChainMap` for combining multiple mappings.
- Recognize the purpose of `UserDict`, `UserList`, and `UserString`.
- Compare collection types and select the appropriate structure.
- Apply collections to practical Network Automation tasks.
- Write maintainable Python code using type hints, functions, and logging.

## 36.3 — Counter for Network Log Analysis

Apply `Counter` to practical log-analysis scenarios.

Topics:

- Counting event types
- Identifying the most frequent errors
- Counting events by hostname
- Analyzing interface status messages
- Producing frequency summaries

Example:

```python
from collections import Counter

event_types = [
    "LINK_DOWN",
    "LOGIN_FAILURE",
    "LINK_DOWN",
    "CONFIG_CHANGE",
    "LINK_DOWN",
    "LOGIN_FAILURE",
]

event_counts = Counter(event_types)

print(event_counts)
print(event_counts.most_common(2))
````

Expected output:

```
Counter({
    'LINK_DOWN': 3,
    'LOGIN_FAILURE': 2,
    'CONFIG_CHANGE': 1
})

[('LINK_DOWN', 3), ('LOGIN_FAILURE', 2)]
```

## 36.5 — defaultdict for Network Device Grouping

Topics:

- Grouping devices by vendor
- Grouping interfaces by hostname
- Organizing events by severity
- Grouping network logs by device
- Building nested data structures

Example:

```
from collections import defaultdictdevices_by_vendor = defaultdict(list)devices = [    {"hostname": "R1", "vendor": "Cisco"},    {"hostname": "R2", "vendor": "Cisco"},    {"hostname": "R3", "vendor": "Juniper"},]for device in devices:    devices_by_vendor[device["vendor"]].append(device["hostname"])for vendor, hostnames in devices_by_vendor.items():    print(f"{vendor}: {hostnames}")
```

Expected output:

```
Cisco: ['R1', 'R2']
Juniper: ['R3']
```

## 36.6 — deque Basics

`deque` stands for double-ended queue.

It supports efficient appending and removing elements from both ends.

Topics:

- Creating a deque
- `append()` and `appendleft()`
- `pop()` and `popleft()`
- `extend()` and `extendleft()`
- Rotating elements with `rotate()`
- Using `maxlen` for bounded queues
- Comparing `deque` with `list`

Network Automation Example:

Maintaining a rolling buffer containing the most recent monitoring events without allowing the buffer to grow indefinitely.

## 36.7 — deque for Network Event Buffers

Topics:

- Creating a bounded event buffer
- Retaining the most recent events
- Removing the oldest events automatically
- Processing events in arrival order
- Understanding queue behavior

Example:

```
from collections import dequeevent_buffer = deque(maxlen=3)event_buffer.append("R1: LINK_UP")event_buffer.append("R2: LINK_DOWN")event_buffer.append("SW1: CONFIG_CHANGE")event_buffer.append("R3: LINK_UP")print(list(event_buffer))
```

Expected output:

```
['R2: LINK_DOWN', 'SW1: CONFIG_CHANGE', 'R3: LINK_UP']
```

Note: `deque(maxlen=3)` automatically discards elements from the opposite end when new elements exceed the configured capacity.

## 36.9 — OrderedDict and ChainMap

### OrderedDict

Topics:

- Understanding insertion order
- Moving elements with `move_to_end()`

Regular dictionaries preserve insertion order in modern Python. `OrderedDict` remains useful when its specialized reordering operations or order-sensitive equality behavior are needed.

### ChainMap

## 36.10 — UserDict, UserList, and UserString

These classes provide convenient wrappers for creating customized dictionary-, list-, and string-like objects.

Topics:

- Understanding the purpose of wrapper classes
- Extending existing container behavior
- Overriding selected operations
- Validating or controlling data access
- Understanding when a custom container is justified

Network Automation Example:

Designing a specialized device registry with custom validation rules.

These classes are advanced tools. Use them when ordinary containers cannot clearly express the required behavior.

## 36.11 — Collections Comparison

Compare the main collection types and their use cases.

| Collection    | Main Purpose                        | Network Automation Use Case      |
| ------------- | ----------------------------------- | -------------------------------- |
| `Counter`     | Count occurrences                   | Event and error statistics       |
| `defaultdict` | Supply defaults for missing keys    | Grouping devices and logs        |
| `deque`       | Efficient operations at both ends   | Monitoring event buffers         |
| `namedtuple`  | Immutable records with named fields | Simple device records            |
| `OrderedDict` | Specialized order management        | Reordering configuration entries |
| `ChainMap`    | Combine multiple mappings           | Configuration precedence         |
| `UserDict`    | Customize dictionary behavior       | Device registries                |
| `UserList`    | Customize list behavior             | Validated collections            |
| `UserString`  | Customize string behavior           | Specialized string wrappers      |
